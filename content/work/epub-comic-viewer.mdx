## 문제

EPUB/Comic 뷰어에서 DRM 복호화를 메인스레드에서 수행하면 뷰어 UI가 블로킹됐습니다. 복호화 연산이 UI 렌더링과 같은 스레드를 쓰기 때문에, 콘텐츠가 무거울수록 페이지를 넘기거나 스크롤하는 동작이 그만큼 늦게 반응했습니다.

뷰어는 사용자가 오래 머무르며 계속 조작하는 화면입니다. 여기서 생기는 지연은 기능 결함으로 보이지 않더라도 읽는 경험을 직접 깎습니다.

## 행동

DRM 정책상 콘텐츠를 열기 전 복호화 과정은 반드시 거쳐야 했습니다. 연산 자체를 없앨 수 없었기 때문에 연산이 도는 스레드를 바꾸는 쪽으로 방향을 잡았습니다.

복호화 파이프라인을 Web Worker로 분리해 UI 블로킹 없는 비동기 처리로 구현했습니다. 메인스레드와 메시지를 주고받는 비용이 새로 생기지만, 그 비용은 페이지 넘김이 멈추는 것보다 감수할 만했습니다.

## 성과

이 작업은 별도로 측정한 수치가 없어 구조적 성과로 남깁니다.

- 복호화 작업이 사용자 인터랙션을 막는 구조적 한계에 대응해, Web Worker 분리로 스크롤과 페이지 전환의 체감 성능을 개선했습니다.
- 뷰어처럼 조작이 잦은 UI에서는 성능 이슈가 만족도에 직접 영향을 주므로, 메인스레드 부하를 줄이는 구조로 전환해 읽기 경험을 개선했습니다.

DRM처럼 보안 제약이 있는 연산은 처리 위치를 옮길 수 있는 폭이 좁습니다. 메인스레드를 비워야 한다는 목표와 연산 자체는 그대로 둬야 한다는 제약이 부딪힐 때, 실행 스레드를 바꾸는 쪽이 남은 선택지였습니다.
